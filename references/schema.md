# 结构定义（schema.md）

标签词跟随会话语言（中文会话用 `[原文]/[出处]/[要求]`，英文会话用 `[quote]/[ref]/[ask]`），类型标签取 types.md 对应列，不另建 i18n 字典。本文件只定义结构，语义判据在 types.md。

## 0. 库根与目录

`$LIB` 解析见 SKILL.md §1（每个动作开头做一次，同一轮不重复）；`root.txt` 只存一行路径，不写注释、不写 JSON，便于手改。

```
$LIB/
├── memory/            真源：一会话一文件
├── handoff_memory.md  全量视图（由 memory/ 重建）
├── handoff_patches.md 判据句规则源（每轮加载、非档案；无则跳过）
└── handoff_report.md  交接产物
```

## 1. 文件命名与解析（本版核心）

### 1.1 命名

```
mem_<agent>_<会话标识>.md
```

- `mem_` 前缀固定，小写；
- `<agent>` = agent 官方名，**其中空格换成下划线**（`WorkBuddy AI` → `WorkBuddy_AI`）；
- `<会话标识>` = 该会话在宿主里的唯一标识，**来源由 adapter 提供、格式不作全局规定**（见 §1.3）；
- 文件名内**不允许空格**；除 `mem_` 与两个分隔下划线外，不再加别的下划线（防止解析歧义）。

### 1.2 解析（从右往左切，唯一算法）

不要「从左往右 split 三段」，agent 名本身可能含下划线（`WorkBuddy_AI`、`DeepSeek_Harness`），左切必错。唯一正确做法：

1. 去掉 `mem_` 前缀与 `.md` 后缀，得 `R`；
2. 在 `R` 里**从右往左**找**最后一个**下划线，切出左右两段：右段 = 会话标识 `S`，左段 = agent 名 `A`；
3. `A` 里的下划线还原为空格，即 agent 官方名；`S` 原样使用；
4. **校验与处置（自足，任何动作都按此办）**：`S` 必须非空且不含空格。
   - `R` 里**没有下划线** → 旧格式聚合文件（`mem_<agent>.md`），按 §6 只读处理，不报错；
   - `R` 里有下划线但 `S` 为空（如 `mem_WorkBuddy_.md`）、`A` 为空、或 `S` 含空格 → 命名异常：**不改文件名**（改名会断链），报给用户并说明两侧证据；交接时按 [template.md](template.md) 的「命名待定」条写进缺口段，由用户定夺。

**为什么不用 UUID 正则**：会话 id 是各产品私有格式（UUID / hash / 目录名都有），把其中一种写死成协议，新 agent 一上来就解析失败。「最后一个下划线」是纯语法规则，与 id 长什么样无关；代价是 agent 名与会话标识都不得含下划线（会话标识天然满足，agent 名由 adapter 归一化保证）。

### 1.3 会话标识怎么取

由 adapter 的 `session_id` 接口给出，见 [adapters/index.md](adapters/index.md)。三种常见形态：

| 形态 | 例子 | 来源 |
|---|---|---|
| 十六进制 UUID | `a224e4fd-1509-42b7-9eb2-7de8f4903e72` | WorkBuddy 系（`CODEBUDDY_SESSION_ID`） |
| hash / 短 id | `9f3c1a…` | Claude Code 等 |
| 目录名或时间戳组合 | `session_v4_20261120T1505` | 无会话 id 变量的宿主，由 adapter 从记录路径派生 |

**取不到会话标识时**（无会话 id 变量、且记录路径也定位不到）：用 `unknown-YYYYMMDD-HHMM` 作标识（前缀与时间全用连字符，**不含下划线**，符合 §1.2 解析约束），并在文件源段写「标识不可得，按启动时间生成」，条目不得写入 `已沉淀` 状态（不可溯源就不该冻结）。

## 2. 文件结构（三段）

```markdown
# handoff3 会话记忆 · <agent 官方名>

## 文件源

- <agent> 会话：`<绝对路径>` · 状态 活跃 · 核对至 2026-11-20 15:05
- <agent> 会话：`<绝对路径>` · 状态 已沉淀（最后更新 2026-11-19 11:42） · 核对至 2026-11-19 11:42

## 正文

- [2026-11-20 15:05] [决策] 用零脚本架构
  - [原文] 把 4 个脚本全砍，verify 降级为格式规则
```

### 2.1 标题

`# handoff3 会话记忆 · <agent 官方名>`——官方拼写照抄（`WorkBuddy` / `WorkBuddy AI` / `DeepSeek Harness` 大小写与空格不改，`Claude Code` 不是 `claudecode`）。

### 2.2 文件源段

一行一个来源，格式固定：

```
- <agent> 会话：`<绝对路径>` · 状态 <活跃|已沉淀> · 核对至 <YYYY-MM-DD HH:MM>
```

- **路径运行时获取、不编造**，反引号包裹（避免 Windows 反斜杠被 Markdown 吃掉）；写法按 §5 第 4 档（根外 → 绝对路径）；
- **只列本文件所属 agent 与该会话的来源**，不列别的 agent / 会话；
- 正常只有一行；多行仅见于旧格式拆分残留、或同一会话记录被轮转（`session.jsonl` 与归档件并存），每行各带独立状态与核对至；
- **状态词只有两个**：`活跃`（可达）、`已沉淀（最后更新 <时间>）`（不可达）。判定只看**路径可达性**，不看静默多久——**静默期不算沉淀**（会话可能只是暂停）；
- `核对至` = 已覆盖到来源的哪个时刻，由条目时间**派生**（见 §4），不是独立计数器。

**为什么删掉水位行**：旧版文末水位恒等于末条条目时间，信息量为零；「该从哪往后读」已由按来源行绑定的 `核对至` 承担。旧版单条水位在两会话并存时被较晚者推高，把另一方缺口整段遮住；一会话一文件后该干扰消失。

### 2.3 正文段

条目按时间**升序**排列，新条目追加在末尾。首行 `## 正文` 之后空一行再写第一条。

### 2.4 视图重建（`handoff_memory.md`）

全量视图不是真源，任何时刻都能由 `memory/` 重新生成。**覆盖写，不追加**：

1. 读 `memory/` 下全部 `mem_*.md`（含旧格式聚合文件），按条目时间**升序**合并；
2. 同一**时间 + quote** 组合出现多次 → 只保留**最早**一条；**只比 quote 会把同轮多条（共用一句原话）误删**，所以去重键必须带上时间；
3. 每条标来源 `[出处]`（`文件名:行`）；来源是旧格式聚合文件时标 `（旧格式聚合）`，文件索引里写明「只读保留」；
4. 头部写重建时间、文件数、条目数；正文分「文件索引」+「时间线」两段；
5. **不写回任何 `mem_` 文件**，也不因重建改状态词或 `核对至`。

**触发时机见 SKILL.md §1.1（三个）**；纯记忆轮不重建。

## 3. 记忆条目（一行一事）

首行是扫读锚点：`时间 + 类型 + 主题概括`；agent 名已由文件名承载，**条目内不再重复写 agent**（旧格式每条都带 `[WorkBuddy]` 前缀，改为按文件归属后即可省略——同一文件内 100 条重复同一个词，纯浪费）。正文含多个并列要点时拆 `[要点]` 子项，每条一行，不写分号串。**条目之间空一行**（纯文本与 Markdown 预览都更易扫读；空行不是新条目，grep 顶层行时忽略）；**条目内部不插空行**，子项紧贴主题行。

```
- [2026-11-17 13:26] [决策] 用零脚本架构
  - [原文] 把 4 个脚本全砍，verify 降级为格式规则

- [2026-11-17 13:41] [代码] workbuddy.md 补 JSONL 原话提取规则
  - [要点] 认 input_text 类型
  - [要点] 丢弃三类系统注入
  - [要点] 只取 user_query 标签内容
  - [原文] 原话提取规则必须照做（否则误杀 311 条原话）
  - [出处] workbuddy.md:70-79
```

| 位置 | 标签 | 说明 |
|---|---|---|
| 1 | 时间 | `YYYY-MM-DD HH:MM`，取自宿主当时时间，不编造。不带时区后缀。从会话记录逐字重放恢复时照抄历史字节，不改写时间标签。**非 `HH:MM` 的写法一律不合格**：`19:1x`、`今天`、`刚才`、`刚刚` 都是占位，等于编造，S3 与 S5 会同时失效 |
| 2 | 类型 | types.md 八类之一，取对应语言列（中文 `[决策]` / 英文 `[decision]`）；`[代码]` 是正交材料标记。**「结论 / 总结 / 记录 / 摘要」不是类型**——出现即判格式错，按 types.md 判据重判 |
| 3 | 主题 | 简短主题概括，可检查的陈述句；并列要点拆下一层，不堆一行 |
| 4 | 要点 / point | 可选：正文有多个并列项时每条一行；短正文无并列项可不写 |
| 5 | 原文 / quote | **必带**（约束、期待、决策、否决、阻塞、事实一律要），原文逐字片段，**永不翻译** |
| 6 | 出处 / ref | 可选：`路径:行`。**时间本身就是出处时不写**，避免与 `[时间]` 重复 |

**条目时间必须是来源记录里真实存在的时刻**——它同时是 `核对至` 的计算依据（§4）和 actions/selfcheck.md S3/S5 的判据。编造或估算会让两个检查同时失效。

## 4. 缺口判据（取代水位）

**派生规则**（不落盘、不维护）：

- 某来源行的 `核对至` **≥ 本文件内属于该来源的条目中最晚的时间**，含义是「该来源已审阅到哪个时刻」；文件里没有条目 → `核对至` = 文件源段写的初始时刻（首次写入时的会话起点）；
- **写入后立即刷新该行的 `核对至`**：新条目必然更晚，就把那一行的值改成新条目时间；只改对应来源那一行，不动别的行。
- **缺口内无实质结论时也要推进**：grep 过该段、确认没有可记内容（纯寒暄 / 系统注入），仍把 `核对至` 推到 `T_end`，表示「已审阅、无需记录」。不推进会让下次交接重复报同一段假缺口。

**缺口判定**（交接的「缺口补写」节、自检 S5 用）：

```
读来源记录的末条时间 T_end
若 T_end > 该行核对至  → 有缺口，缺的是「核对至, T_end] 这段
若 T_end ≤ 该行核对至  → 无缺口
```

比对是时间戳比时间戳，**不需要 grep 探测内容**。这一步比旧版省一次全文件扫描，也是「水位」能退役的直接原因。

**为何不比「最后一条条目时间」而比「核对至」**：两者常常相等，但有一类正当例外——用户在某轮说了纯寒暄（「好的谢谢」），按 §2.1 判据不算实质结论、不记条目，`核对至` 却应推进到该轮到过。把「已审视但无需记录」这件事记在 `核对至` 上，重跑交接就不会反复捞同一段。这正是旧版水位想要但做不到的（它的值被强制等于末条条目时间）。

## 5. `[出处]` 路径写法（管产物）

按文件位置四选一，**最具体者优先**——本技能 references 的判断先于 `$LIB`，`$LIB` 的判断先于「项目根内 / 外」：

1. **本技能 references** → 只写文件名（在 adapters/ 下加目录前缀），如 `adapters/workbuddy.md:25`。虽在项目根外也不写绝对路径。
2. **`$LIB` 内** → 文件名或相对 `$LIB` 路径，如 `handoff_memory.md:9`。**库根绝对路径只在报告「依据」行出现一次**——库可能被搬走，铺满绝对路径等于埋失效锚点。
3. **项目根内、不在 `$LIB`** → 相对项目根，如 `docs/spec.md:25`。
4. **根外**（会话记录、别处资料）→ 绝对路径；相对路径会指向错误位置，读者无法回查。

绝对路径**运行时获取、不编造**，示例里不写本机用户名。**路径后不加解释性括注**（不写「（项目根外，故写绝对路径）」这类说明）——选哪种写法本身就是规则，再补一句只占篇幅。`[出处]` 只留 `路径:行`。

**这条管产物，另一条管技能本体**：SKILL.md / references 自身不写盘符、不写用户目录名，两者不要混。

## 6. 旧格式兼容（`mem_<agent>.md`，无会话后缀）

旧版的聚合文件（一个 agent 一个，条目带 `[agent]` 前缀、文末有水位行）**一律按只读保留**，规则：

1. **识别**：`mem_<agent>.md` 去掉前缀后无下划线 → 按 §1.2 第 4 步识别为旧格式聚合文件，**不报错、不删、不改名**，标「旧格式聚合文件」；
2. **读取**：交接汇总照常读入；条目内有 agent 前缀就取它，没有就取文件名解析出的 agent；
3. **不写入**：新条目一律写进 `mem_<agent>_<会话>.md`；只有新会话尚未建文件、且用户明确要求「继续追加」时才写旧文件；
4. **不自动迁移**：旧文件条目无法可靠判断属于哪个会话（实测 70 条跨 2 会话、48 条在重叠区），强制迁移等于把「不知道」伪装成「知道」。**旧文件原样留着当沉淀**，新内容走新文件，等其自然过时由用户决定归档或删除；
5. **视图合并**：见 §2.4；旧文件来源在视图里标 `（旧格式聚合）`；
6. 若用户明确要求拆分旧文件：按**会话记录的已知时间边界**切块、归属不明的条目**留在原文件**并在报告「缺口与待复核」列明，绝不静默二分；原地更新，不留备份副本。

## 7. Fact（交接渲染中间表示，不落盘）

每条抽取结果在上下文里按 `type / text / quote / ref / time / locale / certainty` 七个字段持有；键名保留 ASCII（不落盘，改中文键名对任何工具没好处）。`certainty`：两边 agent 记忆都有 → `high`；只有一边 → `medium` / `low`，产物标「待复核」。

## 8. handoff_patches.md（判据句）

一条一块，每个子项一行，用户答「是」后才追加：

```
- 背景段必须点明谁 / 要什么 / 卡在哪
  - 并引一处 quote
  - 禁止「前面讨论了很多」这类空泛话
```

判据句要求**可判断**（是/否），不写数字权重、不写评分公式；多条件拆子项，不分号串一行。定期审计「删掉会不会犯错」，不会就删。
