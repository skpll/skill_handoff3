# 更新记忆（actions/update-memory.md）

用于落款没生效、怀疑本会话 mem 文件有问题或缺失。**只处理当前 agent、当前会话的那一个文件**：不读别的文件、不跑自检六步、不重建视图、不出报告。

**前置**：`$LIB` 与 agent / 会话标识按 [adapters/](../adapters/index.md) 取（不硬编码、不扫全局、不参考已有文件名）。需加载 [schema.md](../schema.md) §1–3 与 [types.md](../types.md)。

**不要加载 selfcheck.md**：结构判据（标题、文件源三要素、条目字段、状态词两个）都在 schema §1.2 / §2.1–2.3 / §3；S3/S5/S6 是跨文件判据，本动作不做。

## 1. 定位

算出本会话 mem 路径。存在 → 继续。不存在时先列 `memory/` 目录：若有文件因命名异常（schema §1.2 第 4 步）而无法按名字认出、但其文件源段声明的来源正是本会话 → **就地修它，不新建第二份**（同会话两份记忆等于静默分裂）；没有这样的文件 → 按 [schema.md](../schema.md) §1–3 新建（标题 + 文件源 + 正文）。

## 2. 修结构

核对该文件的标题（schema §2.1）、文件源段（§2.2：路径 / 状态 / 核对至 三要素齐全，状态词只允许 `活跃` 与 `已沉淀（最后更新 <时间>）`）、条目字段（§3：时间 + 类型 + 主题，该带 `[原文]` 的必须带），有错就地修。**时间须是来源记录里真实存在的 `YYYY-MM-DD HH:MM`、类型须属 types.md 八类或 `[代码]`**（判据同 selfcheck S1 的对应两行，别只查「有没有」而不查「合不合法」）。

文件名按 schema §1.2 的算法解析（从右往左取最后一个下划线），但**文件名只是索引、不是判据**。agent 名以 [adapters](../adapters/index.md) 现场判定为准（WorkBuddy 系即 workbuddy.md §1.1 的两条 find），再按下表处置：

| 情形 | 动作 |
|---|---|
| 判定与文件源段不一致 | 改文件源段的 agent 名与标题；**路径与判定不符时一并按判定重写** |
| 判定与**文件名**冲突 | **按判定改文件源与标题，文件名不动**（改名会断链），结论里报「文件名与判定不符，建议改名」；文件已在版本库内 → 附 `git mv` 建议命令，**由用户执行** |
| 判定取不到（两条 find 都无输出）或双方证据冲突 | 不改，在给用户的结论里说明 |

**方向与 selfcheck S2 一致：判定优先于文件名。** 绝不按文件名把文件源改回去——那会把错名写成事实，S2 下一轮再报回来，两个动作互相翻烧饼。

**「结构」的边界**：只修上面这些明列项，加 schema §3 的空行规则（条目内不空行、条目之间空一行）。措辞、标点、条目内容、主题概括一律不动——那是内容，不是结构。

状态 `已沉淀`（来源记录不可达）通常只修错别字、不补写（硬规则 8）；但用户显式发「更新记忆」即视为对该文件的明确指名，若来源记录实际可达，可解冻并正常补写。

## 3. 补缺口

读该文件来源记录的末条时间 T_end。**先对齐起点**：`核对至` 大于本文件末条条目时间时，起点改用末条条目时间（同 [handoff.md](handoff.md) §3，防「本轮先写条目把缺口推平」）；否则起点用 `核对至`。起点 < T_end → 用 grep 只捞起点之后的命中行，按 [schema.md](../schema.md) §3 格式补进本文件、把该行 `核对至` 刷到 T_end。**条目时间必须取来源记录里的真实时刻，不得用当前时间或估算**。**按缺口决定读多少，禁止整读**；来源为压缩格式（如 zstd）→ 不自动补写，如实说明。

**此判据只能查末尾漏记**，查不到中间的空洞或归属错——那两类不在本动作能力内。

## 4. 收尾

本轮确实改动过本文件（新建 / 补写 / 修结构，含只改 `核对至`）→ 按 SKILL.md §2.2 用 **A** 落款；核查后确认文件完好、无改动 → 用 **B**，**不谎称修复过**。

## 5. 边界

**不做 / 查不出**：不读其他会话的 `mem_`（判目标是否存在只列目录；唯一例外是 §1 的命名异常文件，只读其文件源段）、不跑六步、不重建视图、不写报告、不碰 patches；只覆盖「文件缺失 / 末尾漏记 / 文件自身结构错误」，中间漏条目、归属错、时间越界需跨文件比对，转③自检或①交接。

**失败模式**：目标文件已沉淀且来源不可达 → 只修错别字并说明；来源为压缩格式 → 不补写、如实说明；agent / 会话标识取不到 → 按 schema §1.3 用 `unknown-YYYYMMDD-HHMM`，且该文件不得进入 `已沉淀`。
