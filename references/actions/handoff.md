# 交接（actions/handoff.md）

①交接的执行正文。**唯一写报告的动作；已含自检六步**——不必先单独发「自检」。

**前置**：`$LIB` 按 SKILL.md §1 解析，指错即停；读 `$LIB/handoff_patches.md`（存在才读、无则跳过），其判据句对所有步骤生效。**判据句只约束产物写法，不是用户约束**——不得抄进报告「目标与硬约束」段（那里只放用户逐字原话）。需加载：[template.md](../template.md)、[types.md](../types.md)、[schema.md](../schema.md)、[selfcheck.md](selfcheck.md)。

**开跑前先记 C0**：枚举时把每个 `mem_*.md` 当前的 `核对至` 记成 C0，自检 S5 与缺口补写**一律用 C0 判定**，不用后续被自己写过的值。**若本轮已先写过条目**（违反 SKILL.md §3 的固定顺序），C0 已失效——必须在报告缺口段如实写一行「本轮条目先于交接写入，`核对至` 已被推进，历史缺口可能被覆盖」，**不得报「无缺口」**。

## 1. 枚举文件

读 `$LIB/memory/` 下每个 `mem_*.md` 的文件源段，得到 agent / 会话标识 / 来源路径 / 状态 / 核对至。文件名只作索引，**以文件源段为准**；两者不符按 selfcheck S2 处理。

## 2. 自检（S1→S6，顺序执行、固定全跑）

判据与修法严格照 [selfcheck.md](selfcheck.md)。**写入边界两条不许越**：其一，格式修正与状态词 / `核对至` 可跨文件；其二，**条目内容只改自己当前会话的文件**。所有写入**原地更新，不留任何备份副本**。

被 S4 判为 `已沉淀` 的文件即刻冻结，此后连 `核对至` 也不写。**S4 必须在本节内完成，且先于下一节的缺口补写**——它决定状态词与冻结，漏做会往已失效的来源做无用补写、也会写出错误状态。

S5 只报缺口区间不补写、S6 只报缺档不建文件，两类都留给下一节（缺口补写）接手。

**S5 的能力边界**：只比 `核对至` 与 `T_end`，发现的是「末条条目之后」的缺口；中间空洞从时间戳上不可见，报告不得据此声称全覆盖。

## 3. 缺口补写

接手上一节 S5 报出的缺口，**只对仍为 `活跃` 的文件做**。读来源记录末条时间 T_end，`T_end > 核对至` → 用 grep 捞 `核对至` 之后的命中行，只读命中部分，补进**该文件**并更新**该行的 `核对至`**。**按缺口决定读多少，不设文件大小阈值，禁止整读。** 来源为压缩格式（如 zstd）→ 不做自动补写，记入报告缺口段（见 adapters）。

S6 报出的缺档会话同样在此补建文件——只建缺口会话自己的文件，不动别的文件。

**`核对至` 与末条条目时间不等时按条目时间重扫**：`核对至` 更大 → 补写起点改用**末条条目时间**（可能是本轮先写条目把 C0 推平，也可能只是末段只有寒暄；两者从时间戳上无法区分，所以一律重扫一次，补完把该行 `核对至` 刷到 `T_end`，代价只是多读一小段）；`核对至` 更小 → 数据异常，报进缺口段，不自行改时间戳。

## 4. 汇总（只读）

读全部 `mem_` 文件（含旧格式聚合文件），按时间排序、按 quote 去重（保留最早一条）。这是**给报告和视图共用的只读汇总，不回写任何 `mem_`**。同一决策在多个文件都有标「置信高」、只有一边标「待复核」——用 `路径:行` 引用，不复制内容。合并结果连同每条 `文件名:行` 一并留在上下文，**下一节直接用它写视图，不再读第二遍**。

## 5. 重建视图

按 [schema.md](../schema.md) §2.4 的构造规则**覆盖写** `$LIB/handoff_memory.md`——**复用上一节已合并、已去重的结果直接写，不再读第二遍 `mem_`**（两遍全量读是交接轮最大的一笔重复开销）。时机见 SKILL.md §1.1。

## 6. 渲染报告

按 [template.md](../template.md) 写 `$LIB/handoff_report.md`；正文与字段标签跟随会话语言，**原文 quote 与 JSON 键名永不翻译**。

- 缺口段首行按 [template.md](../template.md) 的「覆盖自评」写：N 与 M **真数出来、不许估、不许抄上轮**（M 只数本次写入的条目），K=0 写「无缺口」。**C0 被推平时自评行须写明「已按末条条目时间重扫」**，不得只写「无缺口」。
- **自检结果只出一份**：逐条修复并入报告缺口段，报告外只回一句「自检 N 项已修，详见报告」/「自检无异常」。
- **交人定夺的项**：S2 命名冲突按「命名待定」条、S3 归属或时间越界按「疑似归属错位」条写（格式见 [template.md](../template.md) 缺口段），**不新开章节**。

## 7. 写入边界

照 [selfcheck.md](selfcheck.md) §0 的表执行：格式修正与状态词 / `核对至` 可跨文件（S4 冻结后连这个也不写），条目只改自己会话的文件，来源记录永不写。`handoff_memory.md` / `handoff_report.md` 只有本动作写。所有写入只限 `$LIB` 内（唯一豁免见 SKILL.md 硬规则 10）。

## 8. 失败模式与验收

**失败模式**：`$LIB` 指错或不可读 → 报错停止并写出路径，**绝不回退**；来源为压缩格式 → 跳过补写，报告写明；S2/S3 证据冲突或时间越界 → 不改数据，写进交人定夺；视图或报告写失败 → 如实报错，不谎称完成。

**验收（缺一即未完成）**：
1. 六步全跑过，且 S4 在缺口补写之前完成；
2. 每个 `活跃` 文件的 `核对至` 与来源末条一致（或已在报告里记明缺口原因）；
3. `handoff_memory.md` 已按 §2.4 覆盖写，文件数与条目数与实际一致；
4. `handoff_report.md` 结构齐全（第一屏 + pin 区 + 六段 + 缺口，共 9 个二级标题）且**不新增章节**，缺口段首行是覆盖自评、并含「命名待定」「疑似归属错位」等交人定夺项；
5. 报告外只有一句自检结论，没有第二份逐条回报；
6. 未产生任何 `.bak-*`，未写 `$LIB` 外路径。

**token 纪律**：查缺口用 grep 捞命中行，按缺口决定读多少；禁止把会话记录整体读进上下文。
