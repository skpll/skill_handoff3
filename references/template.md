# 交接稿输出骨架（template.md）

正文语言跟随用户 / 会话语言；段落标题固定中文（结论/待办/否决/阻塞/决策/改动/缺口），不建 i18n 字典。记忆条目的字段标签跟随会话语言，映射见 schema.md / types.md。

结构固定为：第一屏可粘贴消息 → pin 区 → 六段 → 缺口。**不设主题组，不设原始材料专块。**

```
# 任务交接 · <日期> · <主题>

> 读法
> - 面向不了解本技能的接手者，读的人不需要任何前置背景。
> - 先看「新任务首条消息」，可直接复制给接手者。
> - 再按 结论 → 待办 → 否决 → 阻塞 → 决策 → 改动 顺序查看。

> 依据
```

## 纪律

- **第一屏最优先**：「新任务首条消息」必须能直接复制粘贴，读者永远先看它。
- **零背景可读**：读者对本技能一无所知。标题只用裸名词，不写「（直接复制）」「（逐字）」这类暗号；需要交代的在开头「读法 + 依据 + 术语」里一次说清，正文行话就地解释。
- **一行一件事**：主句一行、细节缩进成 `  -` 子项，不用分号串；一句超过约 40 字按语义断开。条目之间空一行。
- **六段顺序固定**：结论 → 待办 → 否决 → 阻塞 → 决策 → 改动；否决段前置（最省接手人时间）。
- **证据摆明面**：结论后附用户原话摘录，读者自行核对，不靠声明「已校验」。
- **原始材料缩写进正文**：见 SKILL.md 硬规则 2。
- **相近条目自然归拢**：六段内用二级标题分组，不引入分组判据、组数上限。
- **缺口必须披露**：单边记忆、未覆盖时段、缺档会话、命名待定、疑似归属错位，全部写进最后一段。
- **覆盖自评必须真数**：第一行固定写 `本轮记忆覆盖：本会话 <N> 个用户轮次 → 新增 <M> 条 mem_ 条目（缺 <K> 条：<原因>）`；N / M 数出来、不估不抄上轮，**M 只数本次写入**，K=0 写「无缺口」。
- **「依据」行**：记忆记录只写库根绝对路径**一次**（schema.md §5 第 2 档的唯一例外），正文 `[出处]` 一律相对 `$LIB` 或文件名。

## 缺口段的七种固定条目

缺口段不是自由文本，按来源分类各占一条，缺哪类就不写哪类：

```
- 本轮记忆覆盖：本会话 <N> 个用户轮次 → 新增 <M> 条 mem_ 条目（缺 <K> 条：<原因>）
- 自检修复：<文件> <哪里错 → 改成什么>（交接内嵌的自检逐条回报并在此，不再对对话单独输出第二份）
- 未覆盖时段：<起 → 止>（来源末条 <T_end>，核对至 <C>）—— 原因：<压缩格式无法 grep / 用户中断>
- 疑似整段未记录：<会话标识>（最后活动 <时间>，来源 <路径>）—— 建议下次交接做完整补写
- 命名待定：<文件> 文件名解析为 <agent>/<会话>，文件源声明 <agent>，两侧证据：<路径归属> —— 待用户确认改文件源还是改名
- 疑似归属错位：<文件> 有 <N> 条在 <时间> 之后，来源只覆盖到 <T_end> —— 待用户确认是否拆分
- 单边记忆：<条目> —— 仅 <agent> 一边有，标「待复核」
```

这七条（含第一行的覆盖自评）是**固定格式**，不按语言翻译结构、只翻译措辞。固定格式的价值是：下一轮交接时能一眼认出「上次报了哪类问题、这次还在不在」。

**「自检修复」与「交人定夺」**：自检的逐条修复归第二类；S2 命名无法定论归「命名待定」，S3 归属/时间越界无法定论归「疑似归属错位」。这两类让用户在报告里完成原「先自检再交接」的中途确认，不猜着改。无修复、无待定项就不写这两类。
